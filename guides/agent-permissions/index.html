Practical guide

Give your agent only the access it needs

Start with one low-risk job, a dedicated account and a small workspace. Enforce the boundary in the operating system, tool configuration and connected service.

Sources reviewed November 14, 2026.

Define the job before granting access

For a reporting agent, begin with read access to the specific source and a place to save a draft. Add sending, publishing or changing records only when that is part of the agreed job. Keep vault administration, recovery methods, billing and unrelated personal files outside its routine access.

A prompt describes your intent. File permissions, account roles, mount rules and tool policy determine what the process can actually reach.

Limit the host and tools

  • Operating-system account: use a dedicated account; avoid running everyday work as an administrator.
  • Workspace: expose the project and output directory it needs. Restrict unrelated home directories, SSH keys and backup material.
  • Container: review writable mounts, network access and capabilities. A container with broad host mounts or a Docker socket can still reach powerful host resources.
  • Tools: enable only the tools required for the job. Check which terminal backend is in effect and how command approvals are configured.
  • Accounts: use narrow service permissions and dedicated browser profiles.

Treat pages, emails and files as untrusted input

A webpage or document can contain text that tries to redirect an agent. Reading it should not authorize new destinations, credential access, purchases or permission changes. Keep consequential actions behind an approval or a narrowly enforced workflow.

Test this with sample content that asks the agent to leave its assigned task. Confirm that it refuses the new action and that the account cannot perform it anyway.

Review an unattended run

  1. Set a bounded task and a clear stopping condition.
  2. Confirm what happens when a tool needs approval and no person is present; do not assume it safely waits.
  3. Review tool activity, changed files, destination services and failures after the first run.
  4. Keep useful audit records with appropriate access and retention. Remove secrets before sharing logs.

Build a stop procedure: pause the job, stop the process if necessary, revoke affected credentials and end website sessions. Repeat the review when permissions or tools change.
