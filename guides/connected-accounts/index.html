Practical guide

Connect accounts without sharing your password

Use a supported integration with the narrowest permissions. Treat OAuth grants, API keys and browser sessions as separate ways to give an agent access.

Sources reviewed November 14, 2026.

Choose the integration that supports the task

Prefer a supported API or OAuth integration for a task it can perform directly. Use browser login when the workflow needs a website and no suitable integration exists. The credentials guide covers vaults and browser sessions.

Review an OAuth grant

  1. Verify the service, application publisher and account on the official sign-in page.
  2. Read the consent screen. Distinguish reading records from sending, deleting, changing permissions or administering a workspace.
  3. Restrict the selected repositories, projects or folders when the integration supports that choice.
  4. Use a test item to confirm the intended operation, then test an action that should be denied.

GitHub Apps offer fine-grained permissions; OAuth app scopes can be broad. A grant cannot add permissions that your account does not already have, but it can expose much of what that account can access.

Store and rotate API keys

Keep model and tool keys out of prompts, skills and memory. Current Agent secret sources can resolve keys at startup through supported secret managers. The manager’s own bootstrap credential still needs protection; a vault does not remove that dependency.

When rotating a key, create a replacement with the intended scope, update the supported secret source, restart or reload as the integration requires, and verify a test call. Revoke the old key at the provider and confirm it no longer works. If it leaked, revoke promptly rather than waiting for the normal rotation window.

Know where to stop access

Remove the app’s grant in the destination service and revoke associated tokens when access is no longer needed. Stop the agent job too. Logging out of WebUI alone does not revoke a service token or close an authenticated website session.

Revocation also does not erase information the integration already copied. Review stored files, memory, logs and service-side retention separately. Keep a short access inventory so you can find every grant during an incident.
